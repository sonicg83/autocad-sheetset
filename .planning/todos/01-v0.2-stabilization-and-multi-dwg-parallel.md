# 阶段 1：v0.2 稳定化与多 DWG 并行

状态：待实施  
建议周期：2～3 周  
阶段目标：让真实项目在故障、重启和多 DWG 处理场景下仍然可恢复、可解释，并在不削弱整批发布安全性的前提下提升 CAD 执行速度。

## 1. 成功标准

- 任意一个 DWG 重建失败时，不发布 DST 或任何 DWG 半成品。
- Worker、API 或计算机异常退出后，能够识别遗留任务并给出恢复、重试或终止结论。
- 用户能从界面查看任务步骤、每个 DWG 的进度、日志和错误建议。
- 历史修订可以预览并“恢复为新修订”，原历史不可被覆盖。
- 单个任务可以同时运行多个 `accoreconsole.exe`，默认并发数为 2，可配置为 1～4。
- 真实多 DWG 项目并行结果与串行结果在 DST 语义、布局顺序、Handle 和文件哈希规则上等价。

## 2. 范围边界

包含：

- 单调度 Worker、单任务内 DWG 分组有界并行。
- 任务领取、状态恢复、失败详情、日志归档、重试和修订恢复。
- 数据库迁移统一和阶段性可靠性测试。

不包含：

- 同时运行多个 `dst-manager worker` 竞争任务。
- 同一工作区并发执行两个写任务。
- 跨机器、远程或分布式 CAD Worker。
- 发布阶段并行替换正式文件。

## 3. 工作包

### S1-01 建立可靠性基线

- [ ] 登记现有 Playwright 失败：任务成功后自动重新打开工作区，导致完成状态立即消失。
- [ ] 建立至少 3 个真实工程的只读结构基线：小型、约 300 张图纸、大布局组。
- [ ] 记录串行执行耗时、每个 DWG 耗时、内存峰值、磁盘占用和 Core Console 失败率。
- [ ] 为所有任务终态和中间态建立状态转换测试。
- [ ] 明确 `FAILED`、`ROLLED_BACK`、`BLOCKED_FILE_LOCK` 的重试资格。

### S1-02 统一数据库迁移

- [ ] 移除业务启动路径中的 `Base.metadata.create_all()` 和运行时 `ALTER TABLE` 迁移逻辑。
- [ ] 所有模型变化通过 Alembic 版本迁移完成。
- [ ] 增加从空数据库升级和从当前 MVP 数据库升级的测试。
- [ ] 增加数据库 schema 版本检查；版本不兼容时阻止写任务并提示升级。
- [ ] 保证只读工作区打开不会在工程目录创建 `.dst-manager/`。

### S1-03 强化任务模型与领取协议

- [ ] 为任务增加 `worker_id`、`attempt`、`started_at`、`heartbeat_at`、`finished_at`。
- [ ] 使用条件更新领取任务：只有 `QUEUED` 状态才能原子变为 `STAGING`。
- [ ] 增加任务阶段明细和 DWG 子任务记录，至少包含目标文件、状态、进度、错误码和日志位置。
- [ ] 定义启动恢复规则：
  - `QUEUED` 保持可领取；
  - 未进入正式发布的遗留 CAD 任务可安全重试；
  - `PUBLISHING/ROLLING_BACK` 必须先完成发布日志恢复；
  - 无法自动判定时标为需要人工检查，禁止直接重跑。
- [ ] 增加安全重试 API；重试创建新 attempt，不覆盖旧日志。

### S1-04 多 DWG 有界并行执行

采用“一个任务调度器 + 多个 DWG 执行单元 + 单线程汇总发布”。

- [ ] 新增配置 `DST_MANAGER_CAD_MAX_PARALLEL`，默认 2，允许范围 1～4。
- [ ] 在并行开始前完成所有源 DWG 哈希确认和只读快照，禁止执行单元直接读取后续可能改名或删除的正式文件。
- [ ] 将 `_rebuild_group()` 改造成无共享可变状态的执行单元，输入包含：
  - 固定执行计划片段；
  - 独立暂存目录；
  - 独立 SCR 和日志路径；
  - 固定 AutoCAD 能力描述；
  - 超时时间。
- [ ] 每个执行单元只返回结构化结果：暂存文件、布局绑定、Handle、耗时、日志和错误。
- [ ] 调度器集中合并 `bindings` 和 `staged_files`，不得由并行线程共同写普通字典。
- [ ] 使用有界执行器调度 DWG 分组；并发数为 1 时必须保持与现有串行行为兼容。
- [ ] 任一执行单元失败后停止提交新单元，等待已启动 Core Console 安全退出或超时终止。
- [ ] 所有单元成功后才更新 AcSm DOM、编码暂存 DST、执行语义往返校验。
- [ ] 正式发布仍由一个线程调用 `RecoverablePublisher.publish()`，保持整批原子语义。
- [ ] 进度按完成的 DWG 数量聚合，并向 SSE 提供当前文件和成功/失败数量。
- [ ] 分别验证 AutoCAD 2016、2020 在并发 1、2、4 下的稳定性；根据资源和许可环境决定发布默认值是否保持 2。

### S1-05 修订恢复

- [ ] 增加按工作区筛选的修订列表和修订详情 API。
- [ ] 从 revision manifest 生成恢复预览：新增、替换、删除的文件及当前哈希冲突。
- [ ] 恢复操作必须作为新任务执行，并创建新的永久 before 快照和新修订。
- [ ] 当前文件与预期基线不一致时阻止恢复，要求重新预览。
- [ ] Web 提供修订详情、恢复确认和完成结果，不直接暴露目录 JSON。

### S1-06 任务可观测性与错误自救

- [ ] 任务成功后保留完成摘要，不因刷新工作区而清空。
- [ ] 增加任务详情 API：状态时间线、DWG 子任务、错误码、日志摘要、重试资格。
- [ ] 为常见错误提供用户建议：CAD 未配置、文件锁、模板变化、超时、磁盘不足、布局或 Handle 不匹配。
- [ ] SSE 断开后自动回退到任务状态轮询，并允许手工重新连接。
- [ ] 日志展示必须脱敏，不回显凭据或不必要的用户目录信息。

## 4. 重点修改入口

- `src/dst_manager/application/cad_job.py`：并行调度、结果汇总和失败取消。
- `src/dst_manager/infrastructure/persistence/database.py`：条件领取、attempt、heartbeat 和子任务。
- `src/dst_manager/infrastructure/autocad/worker.py`：单次 Core Console 执行边界和超时信息。
- `src/dst_manager/infrastructure/filesystem/publisher.py`：恢复预览和恢复发布复用。
- `src/dst_manager/interfaces/api.py`：任务详情、重试、修订详情和恢复 API。
- `web/src/`：任务状态、日志和修订恢复界面。
- `migrations/`：任务和子任务 schema 迁移。

## 5. 测试矩阵

- [ ] 单元测试：并发数限制、结果顺序确定性、部分失败取消、超时、结果合并。
- [ ] 数据库测试：两个领取者不能领取同一任务；heartbeat 过期恢复。
- [ ] 发布测试：并行 CAD 全部成功后发布；任一失败时正式目录零变化。
- [ ] 集成测试：任务详情、SSE、重试、修订恢复和基准修订冲突。
- [ ] Playwright：成功任务保留、失败详情、重试、恢复确认。
- [ ] AutoCAD 2016/2020：2、5、25 布局分组及至少 5 个 DWG 的并发处理。
- [ ] 性能测试：并发 1/2/4 的总耗时、峰值内存和失败率对比。

## 6. 阶段验收

- [ ] Ruff、完整非 CAD pytest、Web 构建和 Playwright 全部通过。
- [ ] 双版本真实 CAD 测试通过，并归档并发对比结果。
- [ ] 注入一个 DWG 重建失败时，正式目录所有文件哈希保持不变。
- [ ] 发布中断后重启应用，发布日志恢复成功且任务状态一致。
- [ ] 历史修订恢复后生成新修订，可以再次恢复回恢复前状态。
- [ ] 并发输出与串行输出语义一致；同一次执行的发布清单顺序确定。

## 7. 风险与回退

- Core Console 并发可能受内存、插件全局资源、临时文件或许可环境影响；并发数必须可降为 1。
- 不允许多个执行单元共享 SCR、Handle 输出或 DWG 暂存路径。
- 发现某 AutoCAD 版本并发不稳定时，可按版本把最大并发强制为 1，不影响其余稳定化功能交付。
