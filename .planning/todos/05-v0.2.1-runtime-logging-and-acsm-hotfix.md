# 紧急修复：v0.2.1 运行时、日志与 AcSm 兼容性

状态：待实施  
优先级：P0，阻断 v0.3 继续开发  
建议周期：3～5 个工作日  
前置条件：停止重复 API/Worker，所有真实工程测试只使用样本副本。  
修复目标：消除真实 AcSm 结构变体导致的晚期任务失败，保证单实例启动与完整停止，并使所有运行日志成为可由普通文本编辑器稳定打开的 UTF-8 文本。

## 1. 事故基线与根因

### 1.1 AcSm 自定义属性晚期失败

已复现的任务包含“新增图纸”和“更新已有图纸自定义属性”。目标 DWG 的暂存重建及 Handle 回读成功后，任务在 `VERIFYING` 阶段失败：

```text
CONTROLLED_PROPERTY_INVALID: Value
```

真实 AcSm XML 中存在以下合法变体：`AcSmCustomPropertyValue` 节点存在，但仅包含 `propname="Flags"` 的 `AcSmProp`，没有 `propname="Value"` 的 `AcSmProp`。经 AutoCAD 实际打开并保存验证，即使输入 XML 显式包含文本为空字符串的 `Value` 节点，AutoCAD 也会自动删除该节点。因此，缺失 `Value` 不是损坏结构，而是 AutoCAD 对空自定义属性的规范保存形式。

同一轮实测还确认 `Flags` 表示自定义属性作用域：`Flags=1` 为 SheetSet 自定义属性，`Flags=2` 为 Sheet 自定义属性。属性身份不能再只按 `propname` 判断，必须同时考虑作用域。当前实现既把前端整份属性表中语义未变化的空值当作写操作，又要求 `Value` 子节点必须恰好存在一个；`clear_others=True` 还未按 `Flags` 限定清空范围，存在越权改动另一作用域属性的风险。这些问题都会被拖到 CAD 执行后的 DOM 更新阶段才暴露。

本次失败未进入 `PUBLISHING`：正式 DST 哈希未变化，原 DWG 哈希未变化，新目标 DWG 未发布，也未生成发布 manifest。

### 1.2 日志不是统一 UTF-8 文本

已观察到：

- `server.stdout.log` 含大量 NUL 字节，被文本编辑器识别为二进制文件。
- `server.stderr.log` 和 `worker.stdout.log` 使用 Windows 系统代码页，按 UTF-8 打开会乱码。
- Worker 向 stdout 输出完整任务 payload、计划和文件详情，日志体积和噪声快速增长。
- 多次启动复用并截断同一日志路径，不同父子进程仍持有文件句柄时可能形成稀疏空洞和 NUL 字节。

### 1.3 启动状态与真实进程不一致

已观察到旧 API 仍监听端口、旧 Worker 仍运行时再次启动：

- 新 API 因 `WinError 10048` 端口占用而退出。
- 健康检查命中旧 API，启动脚本却报告新实例成功。
- PID 状态文件记录控制台启动器，而实际服务由更深层 Python 子进程持有。
- 停止操作只处理状态文件中的 PID，可能遗留 API 或 Worker 子进程。
- 重复 Worker 会同时轮询同一任务数据库，违反当前单调度 Worker 边界。

### 1.4 数据库迁移纪律

测试数据库曾出现 Alembic revision 已是 v0.2，但物理表和字段缺失。根因是已执行的迁移文件在之后继续追加内容，Alembic 不会因同一 revision 文件内容变化而重跑。

历史数据库目前都是可删除测试数据，本修复不要求提供破损测试库的数据保留方案；但必须防止同类版本号与物理 schema 漂移再次发生。

## 2. 成功标准

- 缺少 `Value` 子节点的空自定义属性不再导致 CAD 执行后的晚期失败。
- 空自定义属性以“保留属性容器和 `Flags`、缺失 `Value`”作为规范结果；清空已有非空值时删除 `Value`，不得主动生成空文本 `Value`。
- SheetSet 与 Sheet 自定义属性分别只允许通过 `Flags=1` 与 `Flags=2` 的受控路径修改，同名但不同作用域的属性不得互相覆盖。
- 所有会阻断 AcSm DOM 更新的问题都应在预览或任务进入 CAD 前发现。
- 同一项目只能有一套 API 和一个 Worker；重复启动不得产生新进程。
- `Status` 显示的 API PID 必须就是端口监听者或其受控根进程，Worker PID 必须对应唯一 Worker。
- `Stop` 后不存在属于当前项目的 API、Worker 或其 Python 子进程，端口被释放。
- 每次启动使用独立日志文件；所有日志严格为 UTF-8，无 BOM 要求可统一但不得混用编码，不含 NUL 和非法控制字符。
- 普通文本编辑器可以打开全部日志；中文路径、错误消息和任务摘要显示正确。
- Worker stdout 不再输出完整 payload；完整任务详情继续存数据库和修订目录。
- 新建空数据库与 schema 自检均能确认表、列和 Alembic revision 一致。
- AutoCAD 2016/2020 真实副本测试中，失败不产生任何正式目录半成品。

## 3. 工作包

### H1-01 事故收敛与可复现夹具

- [ ] 增加最小 AcSm XML 夹具：自定义属性节点只有合法 `Flags`、没有 `Value`。
- [ ] 增加包含正常值、空文本、缺失 `Value`、重复 `Value` 四种值结构，以及 `Flags=1`、`Flags=2`、缺失/重复/非法 `Flags` 的参数化测试。
- [ ] 固化 AutoCAD 规范化证据：显式空文本 `Value` 经 2016/2020 打开保存后被删除，非空值与对应 `Flags` 语义保持正确。
- [ ] 固化本次命令组合：新增模板图纸，同时更新已有图纸的图号、标题和三个自定义属性。
- [ ] 记录执行阶段断言：当前缺陷必须可稳定复现为 `VERIFYING → FAILED`，且正式文件哈希不变。
- [ ] 所有真实项目复现只在临时副本执行，不读取后直接修改 `sample/` 原件。

### H1-02 定义 `Value` 与 `Flags` 的受控语义

- [ ] 将属性身份定义为“`propname` + `Flags` 作用域”：`Flags=1` 代表 SheetSet 属性，`Flags=2` 代表 Sheet 属性；同名不同作用域必须分别索引，不得用仅按名称构建的字典静默覆盖。
- [ ] `update_sheet_set` 只允许操作 `Flags=1`，`update_sheet` 和插入图纸属性初始化只允许操作 `Flags=2`；命令作用域与 `Flags` 不匹配时预览阻断，不自动改写 `Flags`。
- [ ] 把缺失 `Value` 定义为 AutoCAD 的规范空值结构。当前语义值和提交值同为空字符串时视为无变化，不触碰 DOM、不创建节点、不报错，即使 Web 回传了整份属性表也一样。
- [ ] 清空已有单个非空 `Value` 时删除该 `Value` 节点，而不是把文本设为 `""`；保留属性容器、唯一合法 `Flags`、未知属性、未知兄弟节点和原有顺序。
- [ ] 对显式存在但文本为空的单个 `Value`，只有用户确实编辑该属性时才删除并规范化；未发生语义变化时保持原 DOM，避免整份表单回传引发无关改写。
- [ ] 缺失 `Value` 后提交非空值时，只有在 `Value` 节点的 `vt`/属性、模板来源及插入顺序已通过 AutoCAD 2016/2020 验证后，才允许受控创建；否则预览返回可理解的阻断诊断。
- [ ] 已存在单个 `Value` 且新值非空时只修改文本，保留 `Flags`、未知属性、未知兄弟节点及节点顺序。
- [ ] 重复 `Value`、重复同作用域同名属性、缺失/重复/非法 `Flags` 时保持阻断，不猜测目标节点或作用域。
- [ ] `clear_others=True` 只处理克隆 Sheet 中 `Flags=2` 的属性，并通过删除 `Value` 恢复未赋值状态；`Flags=1` 的属性及其 `Value` 必须完全不触碰，也不得删除或改写任何 `Flags`。
- [ ] 错误码从宽泛的 `ACSMVALIDATIONERROR` 细化为稳定业务码，至少区分 `CUSTOM_PROPERTY_VALUE_STRUCTURE_UNSUPPORTED`、`CUSTOM_PROPERTY_FLAGS_MISSING`、`CUSTOM_PROPERTY_FLAGS_INVALID`、`CUSTOM_PROPERTY_SCOPE_MISMATCH`、`CUSTOM_PROPERTY_DUPLICATED` 和 `CUSTOM_PROPERTY_VALUE_DUPLICATED`。

### H1-03 把结构校验前移到预览

- [ ] 预览阶段在 AcSm DOM 克隆上执行所有可确定的元数据和结构命令模拟。
- [ ] 预览与正式执行复用同一套自定义属性语义差异计算和 DOM 写入逻辑，先比较当前值与提交值，相同则不产生写操作，避免两套规则漂移。
- [ ] 对插入图纸模板节点、自定义属性名称与 `Flags` 作用域、值节点基数、布局引用数量和受控字段可写性做预检。
- [ ] 不依赖 CAD 结果的 DOM 问题必须使 `executable=false`，禁止入队。
- [ ] 只有 Handle 和重建产物相关校验保留在 `VERIFYING`。
- [ ] Web 展示对象、属性名、原因和用户操作建议，不暴露 XML XPath 或内部异常类名。
- [ ] API 集成测试证明相同请求在修复后不会先启动 Core Console 再失败。

### H1-04 重构单实例进程生命周期

- [ ] 后台服务直接使用确定的 `.venv` Python 入口启动，避免 `dst-manager.exe → python.exe → python.exe` 多层 shim。
- [ ] 状态文件记录 `run_id`、实际 PID、启动时间、命令类型、端口和项目根目录。
- [ ] 启动前检查端口：
  - 端口由本项目受管 API 占用时，返回“已启动”并复用当前状态；
  - 端口由未知进程占用时，明确失败并显示 PID，不自动终止；
  - 状态文件存在但进程不匹配时，标记为陈旧状态并安全清理。
- [ ] 启动 Worker 前按规范化项目根目录和精确命令行检查遗留 Worker；检测到重复时禁止再启动。
- [ ] 健康检查除 `/api/health` 外，还要比对服务返回的 `run_id`，不能命中旧实例后误判成功。
- [ ] `Stop` 按受管进程树结束 API/Worker，等待端口释放并再次枚举确认无遗留子进程。
- [ ] `Status` 分别报告“API 状态文件失效”“端口被旧实例占用”“存在重复 Worker”等异常，而不是笼统显示运行中。
- [ ] 启动任一步失败时回收本次 `run_id` 已启动的全部进程，但不终止未知外部进程。

### H1-05 建立 UTF-8 日志协议

- [ ] 为每次启动生成唯一运行目录，例如 `runtime/<run-id>/`，禁止复用并截断仍可能被持有的日志文件。
- [ ] 启动 Python 时显式设置 `PYTHONUTF8=1`、`PYTHONIOENCODING=utf-8`，并验证 Windows PowerShell 5.1 下生效。
- [ ] API 与 Worker 的 stdout/stderr 分别写入本次运行目录；状态文件指向当前日志路径。
- [ ] 进程启动前创建日志，不允许多个非协调进程以截断模式打开同一路径。
- [ ] 日志写入后必须可用严格 UTF-8 解码，NUL 字节数为 0，除 `TAB/LF/CR` 外控制字符数为 0。
- [ ] Windows 系统错误通过正确代码页解码后再以 UTF-8 写入，不直接把 `mbcs` 字节混入 UTF-8 文件。
- [ ] `Status` 输出当前运行日志路径；增加安全的日志尾部查看方式，不要求用户直接翻找目录。
- [ ] 定义日志轮转和保留策略：按运行实例保存，达到数量或总大小上限后仅清理已停止实例日志。

### H1-06 收敛 Worker 输出与敏感信息

- [ ] Worker 完成任务后只向 stdout 输出单行摘要：任务 ID、状态、attempt、DWG 成功/失败数、总耗时和错误码。
