# 阶段 2：v0.3 日常编辑器

状态：待实施  
建议周期：2～3 周  
前置条件：阶段 1 的任务恢复、修订恢复和并行发布安全已验收。  
阶段目标：把当前演示型表单改造成适合约 300 张图纸工程日常使用的可撤销、可批量编辑界面。

## 1. 成功标准

- 用户无需查看或理解命令 JSON，即可完成主要编辑。
- 变更在提交前可撤销、重做、删除和调整顺序。
- 搜索、过滤、批量选择和跨子集移动在大工程中保持流畅。
- 预览明确说明字段变化、受影响文件、CAD 操作和阻断原因。
- 页面刷新或误关闭后可以恢复未提交草稿。

## 2. 工作包

### E2-01 前端结构重构

- [ ] 将单体 `App.vue` 拆为工作区外壳、项目导航、图纸表格、属性面板、变更篮、预览、任务和历史组件。
- [ ] 建立统一 API 客户端、错误类型和加载状态。
- [ ] 为工作区原始快照、编辑草稿、选中状态和任务状态建立清晰的数据边界。
- [ ] 组件不得直接拼装任意命令字典，命令创建集中到类型化模块。

### E2-02 类型化命令契约

- [ ] 后端为每种命令建立带判别字段的 Pydantic 模型。
- [ ] 明确定义创建、修改、删除、排序子集以及复制、插入、移动、删除图纸的参数。
- [ ] 对位置、图号、名称、来源文件、来源布局和空子集确认执行字段级校验。
- [ ] 生成前后端共享的命令类型说明，避免字段漂移。
- [ ] 保留未知命令拒绝和危险名称校验。

### E2-03 可撤销草稿模型

- [ ] 编辑动作先作用于内存草稿模型，再由原始快照确定性地产生命令序列。
- [ ] 增加撤销、重做、清空和单项移除。
- [ ] 同一对象的重复修改应合并，不无限追加重复命令。
- [ ] 基准修订变化时标记草稿过期，禁止直接执行。
- [ ] 草稿持久化到应用数据目录，不写工程目录；保存工作区、基准修订和编辑动作。

### E2-04 大项目导航和批量编辑

- [ ] 图纸集、子集、图纸三级导航。
- [ ] 按图号、标题、自定义属性和 DWG 文件搜索。
- [ ] 按子集、诊断级别、路径状态和待变更状态过滤。
- [ ] 支持多选、全选当前过滤结果和批量修改属性。
- [ ] 支持拖放排序、跨子集移动和明确的目标位置反馈。
- [ ] 大表格使用虚拟滚动或增量渲染，并保留键盘操作。

### E2-05 补齐编辑能力

- [ ] 创建、重命名、排序和删除子集。
- [ ] 更新图纸集、子集和图纸已有自定义属性。
- [ ] 复制已有图纸布局。
- [ ] 从已检查的 DWG/DWT 模板布局新增图纸。
- [ ] 单子集或选定范围批量重编号。
- [ ] 删除最后一张图纸时单独确认是否删除子集和主 DWG。
- [ ] 不在本阶段支持任意自定义属性 schema、AcSm GUID 或 Handle 编辑。

### E2-06 人类可读预览

- [ ] 按“图纸集属性、子集、图纸、文件操作、CAD 操作、诊断”分组展示。
- [ ] 显示字段的 before/after，而不是原始命令 JSON。
- [ ] 显示将重建、改名、新增和删除的 DWG。
- [ ] 显示预计 Core Console 数量、并发度和预计耗时范围。
- [ ] 阻断诊断提供对象定位和修复建议；点击后回到对应图纸或字段。
- [ ] 执行按钮只接受当前最新且无阻断问题的预览令牌。

## 3. 重点修改入口

- `web/src/`：组件、状态管理、类型化命令和预览。
- `src/dst_manager/interfaces/api.py`：类型化请求、草稿和预览令牌 API。
- `src/dst_manager/domain/planning.py`：新增子集等确定性规划。
- `src/dst_manager/infrastructure/acsm_xml/document.py`：受控结构变更。
- `tests/integration/` 与 `web/tests/e2e/`：API 和主要交互流程。

## 4. 测试矩阵

- [ ] 命令模型正常值、边界值和非法值测试。
- [ ] 撤销/重做、重复编辑合并、草稿恢复和修订冲突测试。
- [ ] 创建/删除子集、批量移动、批量重编号的领域与 XML 回归测试。
- [ ] 298 张图纸数据下的搜索、过滤和滚动性能测试。
- [ ] Playwright 覆盖打开、搜索、多选、批量修改、撤销、预览、执行和完成反馈。
- [ ] 结构命令继续执行 AutoCAD 2016/2020 系统测试。

## 5. 阶段验收

- [ ] 用户可在一个界面完成打开、查找、批量修改、插入、删除、排序、预览和发布。
- [ ] 所有主要操作可在发布前撤销。
- [ ] 刷新页面后能恢复未提交草稿或明确选择丢弃。
- [ ] 300 张规模项目常用交互无明显卡顿。
- [ ] 预览中不再要求用户阅读原始 JSON 才能理解影响。
- [ ] Ruff、pytest、Web 构建、Playwright 和相关双版本 CAD 测试全部通过。

## 6. 风险与回退

- UI 草稿不得成为最终业务规则来源；后端仍需重新规划和校验。
- 拖放和批量命令必须保持确定顺序，不能依赖浏览器对象遍历顺序。
- 前端重构可分组件逐步替换，保留现有 API 主流程直到新 E2E 覆盖完成。
